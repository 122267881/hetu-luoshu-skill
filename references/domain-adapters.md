# 真实需求领域适配器

领域目录存于 `data/application-domains.json`。适配器只改变输入问题、输出模板和边界，不改变河洛九步主循环。

## 领域覆盖

| 领域 | 典型真实需求 | 主要产物 |
|---|---|---|
| 个人选择 | 目标、优先级、习惯、人生选择 | 选项、约束、下一步、复盘日 |
| 关系沟通 | 冲突、误解、边界、谈判 | 利益相关者图、沟通脚本、边界 |
| 学习研究 | 课程、考试、论文、知识体系 | 知识地图、证据计划、学习循环 |
| 职业工作 | 求职、转行、绩效、岗位成长 | 差距图、路径、验证项目 |
| 项目交付 | 范围、进度、依赖、风险 | WBS、负责人、里程碑、风险表 |
| 产品创新 | 用户问题、MVP、定价、验证 | 问题定义、最小产品、实验 |
| 商业战略 | 变现、市场、竞争、客户 | 战略选择、权衡、指标、行动 |
| 组织管理 | 岗位、协作、审批、会议 | 运行模型、RACI、节奏、升级路径 |
| 内容营销 | 定位、内容、获客、转化 | 信息层级、内容计划、测试 |
| AI 系统 | Agent、知识库、自动化、架构 | 架构、路由、数据流、安全门 |
| 故障恢复 | 异常、失败、漏洞、事故 | 止损、假设、排查、恢复、复盘 |
| 日常状态 | 作息、专注、压力、习惯 | 小实验、跟踪指标、复盘 |
| 资源规划 | 预算、现金流、成本、资源 | 场景、限制、分配、监控 |
| 治理风险 | 权限、合规、安全、责任 | 风险表、控制、责任人、监控 |
| 创意设计 | 品牌、故事、视觉、概念 | 方向、评判标准、原型 |
| 跨域复杂问题 | 多个系统纠缠 | 子问题树、路由、统一目标 |

## 适配原则

1. 先路由领域，再路由问题类型。
2. 跨领域请求拆为子问题，但保留一个中心目标。
3. 领域模板不能替代真实数据。
4. 任何领域都必须给指标、失败信号和停止条件。
5. 高影响子问题单独触发专业接管，不因其与低风险问题混合而放宽。
